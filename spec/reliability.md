# ColdGuard 可靠性、通知与责任边界

> **状态**：Vertical Fit 目标。Build 阶段用 TB Alarm + 一种通知即可演示。  
> 完整冷藏 SLO 仅在该垂直成为付费产品后签署进合同。  
> 默认阈值：[industry-pack.md](./industry-pack.md)

漏报、短信失败、无人确认是产品风险，不是运维花絮。合同与 UI 必须写清谁对什么负责。

## 1. SLO（未写入合同前只作内部目标）

付费合同里的数字须单独签署；下表是 Wedge 内部健康线。

| 指标 | Wedge 目标 | 危险信号 |
|------|------------|----------|
| 关键告警产生 → 首条通道「已送达」 | P95 不超过 120 s（critical） | 演练无法证明到达 |
| 确认 SLA 达标率 | Pack 矩阵的 95% | 长期无人 Ack 仍显示「正常」 |
| 演练到达率 | 温度/门磁/断电/离线 **100%** 开单且可 Ack | 只能展示曲线 |
| 断网 | 本地缓存 ≥72 h（60 s × 8 通道量级）；恢复后 `quality=backfill` 补传 | 断网后空洞且无标记 |
| 备份恢复 | Private 档位首次交付前演练一次 | 只有一份磁盘 |

北极星仍是 **Paid Protected Asset-Months** + 闭环 SLA 达标率，见 [coldguard.md](./coldguard.md)。

漏报（真实超阈未开单）按事故处理：写 Incident 类型 `missed_alert`，不得删历史时序。

## 2. 边缘网关必须具备

认证 BOM 内的网关（伙伴硬件）最低能力：

| 能力 | 要求 |
|------|------|
| 本地环形缓存 | 满则丢最旧；满载事件须上报 `buffer_overflow` |
| 本地阈值 | 与当前签名 Policy 一致；云端不可达时仍开本地告警（声光或本地日志 + 复通后上送） |
| 时钟 | NTP；偏差超过 120 s 标 `clock_skew` |
| 补传 | 按 `eventTime` 排序；每条带 `idempotencyKey` |
| 配置 / OTA | 签名包；失败可回滚；变更写 AuditEvent |
| 校准 | 不在网关里「改温度」；只存证书引用 |

云端 Policy 是真源；网关持有**已签名副本**。无签名下发禁止当生产策略。

采样「每小时一次」**不是**本产品约束。默认见 Pack。

## 3. 通知适配器

通知**不是**领域状态。领域只有 Incident / Ack / Escalation。

```text
Incident open → Outbox → Adapter(wecom|dingtalk|sms|…)
                      → DeliveryAttempt (success|fail)
失败 → AuditEvent；连续失败 → Incident type=notify_failure
```

| 通道 | Validation | Wedge |
|------|------------|-------|
| 企微或钉钉（至少一种） | 至少 1 条真实送达 | 必选 |
| SMS | 可选 | 关键升级必选（国内） |
| 微信服务号 / 邮件 | 不做主通道 | 可补充 |
| 电话外呼 | 不做 | 托管值守 SKU 再谈 |

**确认**：控制台 Ack 为主；适配器回传「已读」不能代替 Ack。若某通道支持快捷确认，仍须落到 `Acknowledgement.actorId`。

投递内容最低字段：站点、资产、类型、严重度、开单时间、深链（或工单号）、是否演练。

## 4. 演练协议

上线或每次 Pack 升级后，站点必须跑完一轮标记为 `drill=true` 的演练：

1. 温度超阈（或注入）
2. 门开超时
3. 断电（或网关模拟断电输入）
4. 拔网 / 关上行，验证本地缓存与离线 Incident

全部需要：开单、通知送达记录、Ack、关闭。演练不计入客户损失 KPI，但计入到达率。

无值班表或未完成演练的站点，控制台不得显示「受保护」。

## 5. 责任边界（合同与 UI 免责须一致）

| 失败模式 | SyncroBrain | 渠道 / 硬件商 | 客户 |
|----------|-------------|---------------|------|
| 探头漂移、未校准 | 到期提醒与总览 | 计量与更换 | 按期送检 |
| 漏报（软件未开单） | 事故响应 + 代码修复 | — | 提供复现窗口 |
| 短信运营商失败 | 记录失败并升级第二通道 | — | 提供正确号码与可到达手机 |
| 无人确认 | 按 SLA 升级 | — | 维护值班表 |
| 冰箱本体故障 | 不修冰箱 | 售后 | 维修合同 |
| 园区断网 + 网关缓存耗尽 | 披露缓存窗口 | 硬件规格 | 接受窗口外风险 |
| 传感器精度索赔 | **不**承担制造商责任 | 承担产品责任 | 采购合同相对方 |

托管值守 SKU 把「Ack 值班」转到 SyncroBrain 或指定外包，须另签；默认云订阅**不含** 7×24 代接电话。

## 6. Validation 台架最低证明

不必等 Cloud Lite 产品化，但日志要留：

- 超阈 / 门开 / 断电 / 离线各 1 次
- 断网上行 ≥1 h 后补传，点位带 `backfill`
- 至少 1 条通知真实到达手机或企微

未完成前，不签「告警到达可验证」的试点验收。
